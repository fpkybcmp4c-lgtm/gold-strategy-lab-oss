# 独立部署版变更说明

本版本在全新项目目录和全新 Git 历史中整理，继承可复用的交易界面、数据模型、业务计算及回归测试。原托管站点不属于此仓库的部署目标，仓库不包含它的数据库、身份信息、站点配置、访问凭据或交易附件。

## 为独立使用所作的适配

| 变更 | 原因与影响 |
| --- | --- |
| 云端 D1 数据库接口适配到 Node.js 24 内置 SQLite | 保留原仓储查询与业务层，以本地持久化数据库独立运行，无需云账号 |
| 对象存储适配到本地附件目录 | 截图与数据库一同由使用者管理和备份 |
| 移除托管身份登录与站点发布集成 | 个人部署固定本机监听，无公共注册、共享账号或对原服务的依赖 |
| 使用标准 Next.js 服务运行现有 React / TypeScript 界面 | 去除托管平台专属构建与连接器依赖，降低自行安装要求 |
| 自动建表、数据目录与迁移记录 | 首次运行获得空白环境，重启保留数据 |
| 新增停机备份、校验和恢复命令 | 完整保留数据库与附件，已有目录替换前保留旧副本 |
| 通用化界面名称、默认本金和验证日期 | 清除私人资料和实际账户配置；使用者首次运行需设置自己的参数 |
| 取消默认历史账本单位修正确认与私人规则确认时间 | 不将任何人的历史确认强加给新用户；保留明确确认后的通用处理能力 |
| 示例数据与回归样本采用虚构值 | 不携带真实交易事实，Demo 与正式账本分离 |
| 独立仓库、忽略规则、敏感信息扫描与跨平台 CI 配置 | 控制意外提交数据的风险；实际测试状态以验收报告为准 |
| 加固 Windows 临时目录中的 Git 根目录识别 | 使用文件身份核对目录，避免路径别名造成潜在误判；发现 Git 元数据却无法识别仓库时终止扫描并报告原因，不能跳过历史扫描。该修复的本地扫描回归已通过，跨平台结果以实际 CI 为准 |

## 计算和模型约束

保留现有 G1、S1、S2、L1、L2 的模型分类、计算函数和原始事实优先规则。没有为开源版重新设计交易策略或把未知的费用、风险、币种和历史事实补成确定值。

资金、本金、日期、品种设置及风险参数的通用默认值属于初始化配置，不是历史交易数据。未来改变计算公式、单位匹配或模型定义时，应单独记录原因、数据兼容影响和对应回归测试，不能悄悄重算历史账本。

## 后续维护

每次升级前做完整备份；迁移先在副本验证。依赖升级同时更新锁文件、许可清单和测试。建议优先维护数据完整性、备份可恢复性、合约单位与金额精度、编辑冲突，以及 Windows/macOS 启动流程。

是否创建远端仓库、是否完成各平台验收、未完成项目及已知问题，均以交付时的验收报告和实际仓库状态为准。本文件不将尚未运行的 CI 视为通过。

## 2026-11-03 安全修订

升级 Zod 至 4.6.6，消除已确认的高危集合校验资源消耗漏洞；迁移 Zod 4 的 record/shape API。新增单笔交易集合上限（计划分仓 100 项，开仓/平仓/持仓事件各 1000 项），超限时拒绝保存并保留原数据。新增内存受限回归检查和 CI 依赖审计，同步锁文件、许可记录及验收说明。此修订只属于独立本机版本。
